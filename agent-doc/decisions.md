# Sales Call Tracker - Decision Log

## Round 1

- **Decision 1:** Removing a number from the Do-not-track list needs the manager's password. The Remove button opens a popup showing the number with a secure password field and Cancel / Remove buttons; the app sends only the typed password to the server, and only a server OK deletes the number locally — the row disappears at once and that number is tracked again. Adding numbers and the tracking check stay exactly as today — local and offline — and the list itself stays on the phone only: no server copy, no admin web view, no remote removal, no audit log.
- **Decision 2:** The remove password lives only on the server, in the environment variable `DO_NOT_TRACK_REMOVE_PASSWORD` — the manager sets the real value in the server's .env, `.env.example` carries the name with a placeholder, and one password covers the whole company. It never ships in code or inside the app: the phone sends only what the person typed, so the password can never be pulled out of the APK. Changing the env value and restarting the server reaches every phone at its next removal — no app update.
- **Decision 3:** The check fails closed and answers in plain words. With the env value unset, removal is refused with "Removing is not available yet. Contact support." — nobody removes anything before the manager sets the password. A wrong password answers "Wrong password. Ask your manager." and the number stays, with no lockout — a shared password plus lockout would let one salesperson lock everyone out. No internet: "Removing a number needs the internet. Connect and try again." and the number stays. An empty password shows "Enter the password." and sends nothing. Failed tries stay visible in the server's normal logs.
