# Sales Call Tracker - Decision Log

- **Decision 1:** The tapped-number capture stays, with two fixes, and its final fate waits on one real-phone test. First fix: the manifest's tel: intent filter answers ACTION_DIAL beside ACTION_VIEW, so a phone whose select-a-number "Call" button fires the dial intent can offer our app in Android's chooser; no phone whose skin sends that button straight to its own dialer without asking can ever be caught. Second fix: the login permission pass never overlaps its popups — each step waits until the previous popup is fully closed — so the tapped-number step, last in the pass, always shows on first login; the skip rules stay as they are (already the handler, or refused earlier). After both fixes, if the phone still never offers our app on a real number tap, the feature is removed completely.
- **Decision 2:** The Dialer's Paste button never fills the keypad with non-number text again. It reads the clipboard text, extracts the first real phone number from it with libphonenumber-js — the same library the My List upload uses — and fills the keypad with that number in E.164 form. When the clipboard holds no number, it shows the toast "No number found in what you copied." and leaves the keypad exactly as it was. This kills the glitch where the copied AI prompt filled the number display as a giant text blob over the keypad.
- **Decision 3:** The Calling SIM feature is removed completely, all its related things with it. Settings keeps four rows — WhatsApp, Do not track numbers, Clear local data, Log out. Every call places on the phone default SIM, the app's existing no-SIM behavior. READ_PHONE_NUMBERS is no longer asked anywhere: the login pass asks only the three tracking permissions — CALL_PHONE, READ_CALL_LOG, READ_PHONE_STATE — then the reminders check. The SIM picker screen, its hook, the calling-SIM utility, the SIM bridge, the native SIM module, and the SIM logic inside the call launcher are deleted. The calling-sim spec is deleted, and the Settings spec, screen.md, and the Settings screens drop the Calling SIM row and its screens.
- **Decision 4:** The My List Download button saves a real CSV file on the phone — the share sheet is gone. Tapping Download writes the whole list as one .csv file straight into the phone's Downloads folder, where the Files app and Excel open it. The columns stay Number, Status, Interested, Do not call, Notes, Called date, Called time. The file name carries the save moment as date and full time — like `26-10-2026-18-03-26.csv` — so every download is its own file and never overwrites an earlier one. A toast confirms the save with the file's name and folder.
- **Decision 5:** The tapped-number capture is removed completely, as Decision 1 said it would be — the real-phone test showed phones either never offer our app in Android's chooser or keep sending the tap to their own dialer, so the feature cannot be relied on. The `tel:` intent filter on MainActivity, the native TappedNumber module and its registration, the login-pass tapped-number step (instruction popup, chooser probe, "Don't show again" refusal), the tapped-number link listener, and the keypad fill from a caught number are all deleted. The tapped-number-capture spec is deleted, and screen.md, testing.md, structure.md, and screens/INDEX.md drop the feature. Tracking does not depend on it: calls started inside the app are recorded directly, and calls made outside in any dialer are still caught by the call-log sweep at every app open. The login pass keeps only the three tracking permissions and the reminders check.
