# Sales Call Tracker - Decision Log

## Round 1

- **Decision 1:** In My List, the Interested and Do-not-call summary cards become tappable and open one shared list screen; the Left and Called cards stay plain counts. The screen shows the list's name as its title, one row per number in that state — the number with Call and WhatsApp buttons, the same look as the History rows — newest called at the top, "No numbers here yet." when empty, and a back arrow returning to My List. Everything stays on the phone and works offline; no server change.
- **Decision 2:** The rows act like every other list row: Call dials at once through the shared direct-call flow and the shared post-call popup follows; WhatsApp opens the chosen WhatsApp chat with the first-message setting applied and leaves the list untouched. The flags keep today's rules — a later call that marks the number with the other outcome moves it to the other list.
- **Decision 3:** Each of the two lists carries a Download button that saves only that list's rows as one CSV file in the phone's Downloads folder — the same columns and the same date-time file name as the whole-list download — and a toast confirms the save with the file's name.
- **Decision 4:** The shared post-call popup gains a Call Again button beside Submit, so it shows on the keypad, automated, and My List flows alike. Tapping it saves everything exactly like Submit — the outcome choices, the note, and the schedule answer — then dials the same number again at once, and a fresh popup shows after the second call with nothing preselected. The "Go to next call" checkbox is ignored when Call Again is tapped, the keypad display clears as after any submit, and the automated lead stays claimed for its 10-minute window so the redial hits the same lead. With CALL_PHONE denied the standing fallback applies — the number goes to the phone's own dialer and the call is not tracked.
- **Decision 5:** A bad phone number is dropped, never stored raw. At sync the server checks every row's number against the user's country — a number that is not valid is thrown away with a log line, the same treatment old and out-of-hours calls already get, and the sync still answers success so the phone clears its queue: no call saved, no lead touched, no stats. On the phone the keypad checks the typed number with the saved login country before dialing — an invalid number shows "Enter a valid phone number." and no call is placed. The My List and lead uploads already check validity and stay as they are.
- **Decision 6:** The history table stays lean — no note and no flags on its rows; it is a capped call list and nothing more. On the phone a note lives in two homes: the My List row when the number is in My List, and the booking when the popup's Submit books a schedule. The note keeps riding the sync batch to the server exactly as before.
- **Decision 7:** A notes screen shows before a call when the number has notes — on the Scheduled, History, Interested, and Do-not-call rows, the automated lead card, and My List Start Calling. The screen shows the number, its notes newest first, and a Call button; tapping Call dials through the same flow as before. With no notes the call goes straight through with no extra tap. The keypad never shows the screen, and Call Again never shows it — that call was just served. Cancelling the notes screen places no call and returns to where the salesperson was; an automated lead stays claimed for its 10-minute window.
- **Decision 8:** Notes are a single entity: one note per number, and a new note overrides the last — local or server. The popup's Submit overwrites the note on the My List row when the number is in My List and on the booking when a schedule is booked; the synced note overwrites the lead's note on the server, and in the automated flow the served lead's stored note arrives with the lead — one extra field on the existing next-lead response. The notes popup shows that one note — never a list of notes. A number with no note anywhere has no info icon, no notes popup, and the call goes straight through. The lists work fully offline.
- **Decision 9:** Every row on the Scheduled, History, Interested, and Do-not-call lists carries an info icon, but only when the number has notes. Tapping it opens a small popup with the notes, newest first; the row and its actions stay untouched.
- **Decision 10:** A note is capped at 200 characters. The popup's Notes box stops accepting more at the cap and shows a small N/200 counter beside it. The cap lives in the app's `config.json` as `note_max_length`, so it changes without a code change, and the server truncates any longer note to its own cap as defense.
- **Decision 11:** Two reported problems were checked and dropped. The 10-digit Indian number losing a digit in My List — the salesperson said there is no such bug. The manager web lead upload showing "no internet connection available" — postponed. Neither is work now; either returns only as a new decision.
- **Decision 12:** A booking carries an interested flag, set at the moment the popup's Submit books the schedule: on when that call's popup chose Interested or the number's My List row is flagged Interested. The Scheduled row shows an Interested tag only when the flag is on, and rebooking replaces the booking and sets the flag fresh. Marks that live only on the server never tag, and the history table holds no flags — its 1000-row cap makes it the wrong home.
