# Sales Call Tracker - Decision Log


- **Decision 1:** The salesperson gets a personal calling list — the My List tab. The Dialer's pill switch grows a third item — Keypad | Automated | My List. The list lives only on the phone, in a new local SQLite table, and is never sent to the server; the manager never sees it. The tab shows count chips — Left, Called, Interested, Do not call — and one row per number with its badge: Left, Connected, Not connected, Interested, or Do not call. Upload, Start Calling, Download, and Clear buttons sit on the tab, everything works offline, and Start Calling never dials a Do-not-track number — a listed number is skipped and never recorded. A row is marked called by ANY recorded call to its number, from Start Calling or a keypad dial, matched on the normalized number exactly like lead resolution does.

- **Decision 2:** My List takes numbers three ways: a paste box that accepts any messy text and pulls out every phone-like number, a CSV file picker, and an Excel (.xlsx) file picker parsed on the phone by an Excel-reading library — the exact library is picked at implementation from current maintained options. A "Copy AI prompt" button copies a ready prompt: the salesperson pastes their sheet text and the prompt into ChatGPT, and the comma-separated numbers ChatGPT returns go into the paste box. Every number is normalized to E.164 with the login country before storing. The replace rule: a number already in the list in any state has its old row deleted and is added fresh as Left — re-uploading a sheet re-arms all its numbers; the same number twice inside one upload counts once. The toast reads "Added N numbers." with "M not valid." appended when any parse fails. The list's size cap lives in the app's `config.json` as `my_list_max_numbers` (10000).

- **Decision 3:** A My List row leaves Left after any call attempt. The first recorded call to the number — connected or not — moves the row to Called with the outcome and note saved on it; Left counts numbers never dialed. Download exports the whole list as a CSV — number, status, interested, do-not-call, notes, called date — through Android's share sheet; each row keeps its date, so today's slice is a filter in the spreadsheet app. Clear wipes the whole list after a confirmation that shows the counts — left and called — and touches nothing on the server.

- **Decision 4:** Every post-call popup — keypad, automated lead, and My List alike — carries the same two optional outcome buttons, Interested and Do not call again, plus an optional Notes box; nothing is preselected and Submit works with all of it empty. The two choices are saved on the call record as yes/no flags — interested yes or no, do-not-call yes or no — beside the note: the phone's pending row and the server's calls table both carry the two flags and the note, so they ride the normal batch sync. The call's time and duration still come only from the call log — the label never changes any number.

- **Decision 5:** A call's outcome reaches its lead. When a synced call matches a lead, the lead stores the call's outcome and note beside its own state: Do not call again sets the lead's status to stopped — never served again by any salesperson, even unconnected — with claims and schedules cleared; Interested is stored as a label and the normal retry rules keep running unchanged; a call with no outcome resolves the lead exactly as before.

- **Decision 6:** One shared manager login works for everyone at once. A sessions table on the server holds one row per login, and every session stays valid — a new login never signs an older device out, so several managers keep the dashboard open from their own phones and laptops on the same account. The rule is one for every account: salespeople included, so one salesperson login may sit on two phones. Changing the account's password signs every other device out while the device making the change stays in, and deactivating or deleting the account signs out everything. Each stored token from the old single-token column becomes one session row, so the update signs nobody out; the login lockout is unchanged and there is still no logout endpoint — the phone clears its own token.
